# Архитектура Family VPN

Документ описывает текущие границы Family VPN. Этапы 1–2 реализованы. Этап подготовки production-развёртывания описан в `docs/deploy.md`. Установщик на боевом VPS не запускался.

## Состав

1. **Admin** — приложение Next.js. Один администратор, страницы Обзор, Серверы, Конфигурации, Настройки.
2. **Backend** — серверная часть того же приложения: серверные действия, SQLite, маршруты `/api/agent/*`.
3. **Agent** — процесс в каталоге `agent/`. Сам открывает HTTPS к панели. Обычный HTTP принимается только для `127.0.0.1` и `localhost`, когда панель видна через SSH-туннель. Публичный порт управления на VPS не нужен.

Аккаунтов получателей VPN, регистрации, тарифов и платежей нет.

## Этап 1, уже в приложении

- Локальная база SQLite в каталоге `data/` или в `FAMILY_VPN_DATA_DIR`.
- Одна учётная запись администратора. Пароль — scrypt-хеш.
- Сессия: cookie `HttpOnly`, `SameSite=Lax`, в production ещё `Secure`.
- Ограничение попыток входа. Проверка `Origin`. Журнал без секретов.
- Записи серверов в базе. Без агента статус — «Не подключён».

## Этап 2, агент и привязка

Агент генерирует одноразовый код (~100 бит) и ключ Ed25519, вызывает `POST /api/agent/enroll`. Код в базе — только SHA-256. Администратор вводит код в «Добавить сервер». `POST /api/agent/poll` с подписью выдаёт токен. Дальше `POST /api/agent/heartbeat` с `Authorization: Bearer`.

Код живёт 15 минут, принимается один раз, перебор ограничивается. Отзыв гасит токен. Online — только свежий heartbeat и поднятый `wg0`.

## Подготовка production

- Docker Compose: панель + Caddy, volume для SQLite, HTTPS.
- Публичные артефакты агента только под `/releases/*`.
- Установщик 0.3.0 скачивает бинарник с панели и сверяет SHA-256.
- Перенос локальной базы с Windows: `scripts/export-windows-data.ps1` и `scripts/import-panel-data.sh`.
- Сценарий уже настроенного VPS: `docs/vps-connect.md`. Без подтверждения на VPS ничего не ставится.
- Проверка через SSH-туннель использует `http://127.0.0.1` только на самом VPS. Удалённая панель по-прежнему на HTTPS.

## Что сознательно отложено

- Статистика трафика и выпуск конфигураций.
- Автоматическое выполнение Compose или установки на боевой VPS.
- Адрес конкретного VPS и его ключи в Git не хранятся.

## Конфигурации, этап 4

Одна конфигурация принадлежит одному серверу. Приватный ключ клиента не хранится открытым текстом. Отзыв peer — только через агент на том VPS, где peer создан.

## Несколько VPS, этап 5

Серверы независимы. Ключи и подсети одного сервера не используются на другом.

## Self-hosting

`FAMILY_VPN_TRUST_PROXY=1` включается только за своим Caddy. Иначе панель не доверяет `X-Forwarded-*`.

Добавление VPS не требует остановки панели: это новая запись и новая сессия агента.
